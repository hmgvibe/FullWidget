# 程式簽章（SignPath）— 說明

日期：2026-11-02

## 結果

FullWidget 改成開源，準備申請 [SignPath Foundation](https://signpath.org/) 的免費程式簽章。這邊能做的都做好了，只在本機提交，倉庫還是私人的。剩下的步驟要你自己來，見最後一節。

簽章後，Windows 會顯示發行者「SignPath Foundation」，不再是「未知的發行者」。SmartScreen 的藍色警告要等下載的人多了才會消失，簽章不能讓它馬上消失。

## 做了甚麼

**授權**
- `LICENSE`：GNU GPL 3.0（從 gnu.org 下載的官方全文）。別人可以改、可以商用，但發佈修改版時也要用 GPL 公開原始碼，所以沒人能拿去做成閉源產品。
- `sdk/LICENSE`、`templates/LICENSE`：MIT。別人寫的組件可以用任何授權，包括不開源；組件市場的投稿也不受 GPL 影響。
- **名字和 logo**：README 寫明「FullWidget」和 logo 不在授權範圍內，修改版要改名、換圖標。
- 程式的檔案資訊寫上「Copyright (C) 2026 hmgvibe. Licensed under the GPL-3.0.」；發佈的 zip 裏附 `LICENSE`。

**清掉別人的內容**
- 檢查專案時發現兩處別人的內容，開源和 SignPath 都不允許：
  - **每日圖片**的 9 張預覽圖：Bing 每日圖片裏一張 Getty Images 的照片。
  - **`docs/m8` 的三張截圖**：一張 Adobe Stock 的照片和中央社的新聞標題。
- 每日圖片和新聞訂閱的預覽圖改用自己的內容：
  - `build/preview-photos` 裏畫出來的湖景。
  - 自己寫的新聞標題。
  - `build/make-previews.mjs` 新增 `{photo:檔名}` 的寫法，用來放這類自備的圖片。
- 重拍了這兩個組件的 18 張預覽圖（3 套主題 × 3 種語言 × 2 個組件）。`docs/m8` 的三張截圖改用這些預覽圖重新拼成。
- **舊圖還在 git 歷史裏**，公開前要清掉（見最後一節）。
- **已上傳的 v1.1.0 Release** 裏的 zip 也帶着那張 Getty 照片，公開前要刪掉。

**README**
- 新增「授權」、「Code signing policy（程式簽章政策）」、「隱私」三節，中英文都有。這是 SignPath 要求的：
  - 簽章政策：寫明由 SignPath.io 免費簽章、SignPath Foundation 提供證書。
  - 成員和角色：提交、審核、核准都是 hmgvibe。
  - 隱私：列出每一個會連網的地方和原因。

**自動發佈**
- `build/publish.ps1` 分成兩步：`-Step build` 只建置，`-Step pack` 只壓縮，中間可以簽章。不加參數照舊一次做完。
  - 現在只會刪除同版本的舊檔，舊版本的 zip 會留着。
- `.github/workflows/release.yml`：推一個 `v1.2.0` 這樣的標籤時：
  1. 在 GitHub 上建置兩個版本。
  2. 檢查標籤和 `FullWidget.csproj` 的版本一致。
  3. 只把 `FullWidget.exe`、`FullWidget.dll` 送去 SignPath 簽章。.NET 和 WebView2 的檔案已經有微軟的簽章。
  4. 檢查簽章有效。
  5. 壓縮，建立一個**草稿** Release，由你在 GitHub 上看過後按發佈。發佈說明裏有 Code signing policy 和隱私的連結。
- 還沒設定 SignPath 時，跳過簽章，照樣建置。在 Actions 頁手動執行時，zip 放在執行結果裏，不建立 Release。

## SignPath 那邊的設定（申請通過後）

- 專案名稱（project slug）：`FullWidget`。
- 簽章政策（signing policy slug）：`release-signing`，每次都要手動核准。
- Artifact configuration：送去的檔案是兩個資料夾裏的 `FullWidget.exe` 和 `FullWidget.dll`，共 4 個。建議：

```xml
<?xml version="1.0" encoding="utf-8"?>
<artifact-configuration xmlns="http://signpath.io/artifact-configuration/v1">
  <zip-file>
    <pe-file-set>
      <include path="*/FullWidget/FullWidget.exe" min-matches="2" max-matches="2" />
      <include path="*/FullWidget/FullWidget.dll" min-matches="2" max-matches="2" />
      <for-each>
        <authenticode-sign />
      </for-each>
    </pe-file-set>
  </zip-file>
</artifact-configuration>
```

SignPath Foundation 的專案通常由他們協助設定，以他們給的設定為準。

## 本機驗證

- `publish.ps1 -Step build` 再 `-Step pack`：兩個 zip 正常產生（3.8 MB、47.9 MB），裏面有 `LICENSE`，exe 的版權資訊正確，舊的 1.0.0 zip 沒被刪。
- 每日圖片和新聞訂閱的新預覽圖，三套主題都看過。
- `release.yml` 用 YAML 解析器檢查過格式。

## 沒驗證

- **`release.yml` 還沒在 GitHub 上跑過**：要先推上去。倉庫私人時也能跑，只是不會簽章。
- **SignPath 的簽章步驟**：要等申請通過才能測。
- **Artifact configuration** 的寫法是照 SignPath 文件寫的，沒有實際送審過。
- **啟動器的預覽圖**裏有 Windows 的系統圖標（檔案總管、記事本等），是螢幕截圖。一般開源專案都這樣放，但嚴格來說是微軟的圖。

## 你要做的事（按順序）

1. **看一遍** README 的授權、簽章政策和隱私三節，內容對不對。
2. **打開 GitHub 的兩步驟驗證**（Settings → Password and authentication）。SignPath 要求所有成員都開。
3. **告訴我可以公開**。我會做這幾件事，每一件都要你點頭：
   - 把 git 歷史整理成乾淨的一個提交，強制推送，舊的 Getty 照片從歷史裏消失。
   - 刪掉舊的 v1.1.0 Release。
   - 把倉庫改成公開。
   - 推 `v1.2.0` 標籤，由 GitHub 建置一個未簽章的草稿 Release，你看過後發佈。SignPath 要求專案已經有發佈的版本。
4. **申請 SignPath**：到 <https://signpath.org/apply> 填表。這要你自己填，表格會問倉庫網址、授權、成員等。
5. **通過後**：
   - 在 SignPath 建一個 CI 使用者，產生 API token。
   - 在 GitHub 倉庫的 Settings → Secrets and variables → Actions 裏加上：
     - 變數 `SIGNPATH_ORGANIZATION_ID`
     - 密碼 `SIGNPATH_API_TOKEN`
   - 之後每次推版本標籤，就會自動簽章，等你在 SignPath 按核准。
