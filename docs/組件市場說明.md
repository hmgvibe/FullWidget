# 組件市場 — 說明

日期：2026-11-02

## 結果

做了一個放在 GitHub 上的組件市場，和控制中心裏的「線上」分頁：

- **市場本身**是一個 GitHub 儲存庫（在本機的 `market/` 資料夾，還沒推上 GitHub）。
  - 每個組件一個資料夾，大家用 pull request 投稿。
  - 自動檢查會審核投稿。
  - 合併後由 GitHub Pages 發佈網站、組件清單 `index.json` 和每個組件的 `.fwz`。
- **控制中心**：「添加組件」頁上方多了「已安裝 / 線上」切換。
  - 「線上」列出市場裏的組件，可以安裝、更新或放到桌面。
  - 有新版本時，「線上」旁邊會出現數字。
- 市場網址預設是 `https://hmgvibe.github.io/fullwidget-market/`，和現有的 `hmgvibe.github.io` 個人網站互不影響。免費帳號可以這樣做，只要儲存庫是公開的。

## 投稿到上架

1. 投稿者 fork 儲存庫，把組件放進 `widgets/帳號.組件名/`，開 pull request。
2. GitHub Actions 執行 `scripts/check.mjs`，結果列在 pull request 下面：
   - **❌ 要修好才能合併**：
     - id 不合規則或和資料夾名稱不同；用了內建或本機專用的 id（`fullwidget.`、`user.`）。
     - 缺 name、version 寫錯、找不到頁面或圖標。
     - FullWidget 不認識的權限。
     - `.exe`、`.dll`、`.bat`、`.ps1` 這類檔案，或捷徑和符號連結。
     - 超過 5 MB 或 300 個檔案。
     - 更新時版本沒有提高。
   - **⚠ 給審核的人看**：
     - 要連到任何網站（`network:*`）。
     - 要打開電腦上的程式（`shell.launch`）。
     - 從網上載入程式碼。
     - 用了 `eval`。
   - 檢查只讀檔案，不執行組件的程式；pull request 的檢查只有讀取權限。
3. 維護者（你）看過後合併。
4. 合併到 main 後，`scripts/build.mjs` 打包每個組件、產生 `index.json` 和網站，發佈到 GitHub Pages，幾分鐘內上架。

## 安裝和更新（FullWidget 這邊）

- 控制中心讀 `index.json`，十分鐘內不重複下載，並存一份在本機。
- 按「安裝」或「更新到 vX」：
  1. 下載 `.fwz`，核對清單上的 SHA-256。不符就不安裝，並顯示「下載的組件和市場清單對不上」。
  2. 交給原本的安裝畫面：列出組件要的權限，註明「來自組件市場」，用戶同意才裝上。
  3. 更新時，桌面上的那個組件保留原來的位置和設定。
- 只接受 https 的市場網址；http 只限本機（測試用）。
- 有第三方組件的人打開「添加組件」時，會在背景看一次市場，有更新就在「線上」旁顯示數字。只有內建組件的人，要點「線上」才會連到市場。

## 網站

- 搜尋、分類、切換三套主題看預覽圖，網站會自動選繁中、簡中或英文，也可以手動切換。
- 點組件打開詳情：
  - 三套主題的預覽圖。
  - 它可以做什麼，每個權限一句話說明。
  - 版本、更新日期、大小和 SHA-256。
  - 「下載 .fwz」和「原始碼」按鈕。
- 手機寬度也能用。

## 兩個範例組件

市場一開始不會是空的：

| 組件 | 內容 | 權限 |
|---|---|---|
| 每日一句 `hmgvibe.proverb` | 每天一句古人的話（論語、老子、李白、富蘭克林……都已是公有領域），點一下換一句；簡中用 Windows 的簡繁轉換 | 不需要 |
| 護眼提醒 `hmgvibe.eyebreak` | 20-20-20 法則：每 20 分鐘提醒看遠處 20 秒；用 Windows 通知，組件隱藏時也會提醒 | 通知 |

## 實機驗證

用本機的測試伺服器代替 GitHub Pages，把 FullWidget 指到它（環境變數 `FULLWIDGET_MARKET`）：

- **列表**：「線上」列出兩個組件，預覽圖跟着全局主題。
- **安裝**：用滑鼠按「護眼提醒」的「安裝」→ 出現安裝畫面，列出「顯示通知」→ 按「安裝並放到桌面」→ 組件出現在桌面，通知權限已允許，它也預約了 20 分鐘後的提醒。
- **更新**：市場改成 1.0.1 →
  - 「線上」旁出現 1，卡片顯示「更新到 v1.0.1」。
  - 安裝畫面寫「從 1.0.0 更新」。
  - 更新後桌面上的組件還在，數字消失。
- **被改過的檔案**：故意改壞市場上的 `.fwz` → 拒絕安裝，什麼都沒裝上。
- **離線**：
  - 有存過清單時，顯示上次的清單和提示。
  - 沒存過時，顯示「連不上組件市場」和「重試」。
- **自動檢查**：拿一個故意寫錯的組件測試，抓到 6 個錯誤（id、name、version、不認識的權限、`.bat` 檔案、資料夾名稱）和 3 個提醒。
- **網站**：桌面寬度、手機寬度、詳情視窗都看過。

## 沒驗證 / 要知道的

- **還沒推上 GitHub。** 建立公開儲存庫、推上去、開啟 GitHub Pages 要你同意後才做。推上去之前，FullWidget 的「線上」會顯示「連不上組件市場」。
- **GitHub Actions 的兩個工作流程**（檢查 pull request、發佈網站）只在本機跑過裏面的指令，還沒在 GitHub 上實際跑過。
- **FullWidget 本身還沒有下載的地方。** 市場網站寫了「需要 FullWidget 1.1.0 以上」，但沒有地方讓人下載 FullWidget。可以把 `dist\` 的兩個 zip 放到 GitHub Releases。
- **授權。** 儲存庫沒有放 LICENSE。投稿指引要求投稿者有權發佈組件的內容，可以自己附 LICENSE。市場本身用什麼授權（例如 MIT）由你決定。
- **「線上」的市場網址**目前不能在控制中心裏改，只能改設定檔的 `marketUrl` 或用環境變數 `FULLWIDGET_MARKET`。

## 給開發者

- **新檔案**：
  - `src/FullWidget/Core/Market.cs`：讀清單、下載、核對、交給安裝畫面。
  - `market/`：市場儲存庫，包括 `scripts/`、`site/`、`.github/workflows/`、`widgets/`、`README.md`、`CONTRIBUTING.md`。
- **控制中心新指令**：`market.list`、`market.install`、`market.open`。
- **`build/make-previews.mjs --from market/widgets`**：替其他資料夾的組件拍預覽圖，範例內容讀 `market/previews.json`。
